# お題バトル

承認された6画面のデザインに合わせ、メニュー → お題一覧 → お題の詳細 → 対戦準備 → バトル → 結果を実装。
紙の背景・墨色の二重枠・朱色の操作・藍色の相手表示は既存のRetroUiを使用。

| お題 | 条件 | 相手 | 初回クリア称号 |
|---|---|---|---|
| 一文字の可能性 | 文字「一」で勝つ | 刀 / M / 両手 / カウンター | 一の使い手 |
| 小よく大を制す | Sサイズで勝つ | 大 / XL / 両手 / 猛攻 | 小さな挑戦者 |
| 鉄壁突破 | 相手に勝つ | 盾 / M / 両手 / 鉄壁 | 鉄壁の突破者 |
| 一撃の美学 | 必殺技の直接ダメージでKOする | 刀 / M / 両手 / カウンター | 一撃の美学 |
| 声援の力 | 声援を使った試合で勝つ | 闘 / M / 両手 / 猛攻 | 声援の力 |
| 挑戦者の証 | 相手に勝つ | 龍 / L / 両手 / 猛攻 | 挑戦者の証 |

全お題を最初から選択可能。「すべて」「未クリア」「クリア済み」のフィルターを用意。
詳細画面で相手の装備・必殺技と攻略のヒントを確認できる。
準備画面では相手は変更できず、お題指定の文字・サイズをUIとデータの両方で固定する。
指定のない文字・字体・サイズ・持ち方・握る位置・戦い方・反転・必殺技は通常のカスタマイズと同じ仕組みで変更できる。

結果画面の操作：

- 「構成を変えて再挑戦」：保存した構成を引き継いで準備へ。
- 「もう一度戦う」：同じ構成・新しいseedで再戦。
- 「次のお題へ」：クリア時に次のお題の詳細へ。最終お題では一覧へ。
- 「お題一覧へ」：他のお題を選び直す。

勝利しても追加条件が未達成ならクリア・報酬にはならない。敗北・引き分けも再挑戦可能。
「一撃の美学」は既存AchievementMatchRecorderのspecialFinishとKO結果の両方を判定し、必殺でない攻撃や環境ダメージの決着は対象外。
「声援の力」はローカル側の成功した声援イベントを判定し、COMだけの声援は対象外。
観戦・必殺・声援・踏ん張りは既存BattleInterventionを利用する。

保存：PlayerPrefs `MojiBattle.Challenges.v1`。お題ごとの構成・クリア状況・試合数・最短クリア時間を保持する。
通常対戦の`MojiBattle.Builds.v1`と独立して保存し、通常対戦・大会・友人対戦へ戻るとお題の制約を解除する。
称号ID 51〜56を追加。従来のID 1〜50を維持し、称号画面に「お題」カテゴリと墨の輪・月桂樹・文字のメダルを追加した。
報酬は重複しない。称号をデータ画面で初期化した場合は、クリア済みお題の再クリアで再獲得できる。

設定は詳細・対戦・結果画面から開ける。ローカル対戦中は一時停止し、閉じると前の状態に戻る。
タイトル画面には設定ボタンを追加していない。
画面中のHP・能力値・必殺名・クリア数・称号数は実データを表示する。
生成画像に含まれた「一閒」の表記は、実装では既存の正しい必殺名「一閃」を使用する。

主なコード：ChallengeCatalog / ChallengeRuntimeStore / ChallengeScreen / ChallengeResultScreen。
新規シーン：Assets/Scenes/Challenges.unity。
新しいエディター環境では `MojiBattle/Setup Challenge Scene` でシーンを追加でき、WebBuildもこの処理を実行する。

実画面とデザインの比較：Reports/UI/Challenges/index.html。
動作・表示の検証：Reports/challenge-edit.xml、Reports/challenge-regression.xml。
